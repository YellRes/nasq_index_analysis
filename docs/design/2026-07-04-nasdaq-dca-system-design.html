1. 目标与边界

一句话定义：每月定时产出一份"纳指 100 该投多少"的规则化建议报告，并在市场大幅波动时即时提醒，帮助使用者克服人性、纪律化定投 QQQ / 纳指 ETF。

✅ 做什么

  • 每月 1 日生成定投报告：估值 / 回撤 / 利率 / 情绪四维信号 → 按规则给出本期定投倍数
  • 每日静默检查触发条件（如回撤破 -20%），仅在触发时推送提醒
  • AI 结合当期数据给一段宏观点评（参考性质，不影响规则输出）
  • 记录每期信号与建议的历史，可回看规则表现

🚫 不做什么（YAGNI）

  • 不做个股分析、不做自动下单、不做实时行情
  • 不做 Web 仪表盘（v1 不做，报告本身就是 HTML，够看）
  • 不做策略回测框架（先跑起来，之后有需要再补简单回测）

2. 总体架构

GitHub Actions 定时触发→ Python 拉取数据→ 规则引擎计算→ AI 点评（可选）→ 渲染 HTML 报告→ SMTP 邮件推送

两条定时流水线

工作流频率行为
monthly-report.yml每月 1 日（美东收盘后）完整报告 + 定投建议，无论如何都发
daily-check.yml每个交易日一次只算触发条件，触发才发，平时静默

项目结构（示意）

stock-analysis/
├── .github/workflows/     # 两个定时工作流
├── src/
│   ├── datasources/       # 每个数据源一个模块，统一接口
│   ├── rules.py           # 定投规则引擎（纯函数，可独立测试）
│   ├── commentary.py      # AI 点评
│   ├── report.py          # HTML 报告渲染（Jinja2 模板）
│   └── notify.py          # 邮件发送
├── config.yaml            # 规则参数（倍数档位、阈值）全部集中在这
├── history/               # 每期信号与建议的 JSON 存档
└── tests/

设计原则：规则引擎是纯函数（输入信号 → 输出倍数），不碰网络不碰 IO，方便单测和日后回测复用。数据源模块统一返回标准结构，坏一个不影响整体（降级出报告并标注缺失）。

3. 信号体系与数据源

信号指标数据源可靠性
趋势/回撤（主信号） 距历史最高点回撤 %、200 日均线位置 yfinance：^NDX（纳指100）日线 高免费无 key
利率环境（主信号） 10 年期美债收益率及 3 个月变化方向 FRED API（免费 key）；备用 yfinance ^TNX 高
估值（辅助信号） 纳指100 PE 所处近 10 年分位 ⚠️ 无理想免费源，方案见下 中
情绪（辅助信号） VIX 水平 yfinance：^VIX 高
⚠️ 估值数据是唯一的硬骨头：纳指 100 整体 PE 没有权威免费 API。候选方案： ① 用 QQQ 的 trailingPE（yfinance 可取但时有缺失）； ② 自算：取 ^NDX 点位 ÷ 成分股加权盈利（工作量大）； ③ 推荐：v1 先用"盈利收益率替代法"—— 用 QQQ trailingPE 可得时记录并积累历史，取不到就降级为"估值信号缺失"，报告如实标注。估值本来就是辅助信号，缺了不影响主规则。

聊天中确认过的设计取向：纳指过去 15 年长期"贵"，PE 分位择时容易一直空仓踏空，所以回撤 + 利率是主信号，估值只做参考展示。

4. 定投规则引擎（核心）

基准：每月 1000 元人民币（记为 1.0x）。系统只输出倍数与金额，标的无关——执行时可买 A 股 513100（QDII）、QQQ 碎股或 3086.HK，切换标的不需要改系统。规则自上而下匹配，取第一条命中的：

#条件（基于 ^NDX 距历史高点回撤）本期定投倍数单月金额含义
1回撤 ≥ 30%2.0x2000 元历史级机会（2000/2008/2022 级别）
2回撤 ≥ 20%1.5x1500 元技术性熊市，显著加码
3回撤 ≥ 10%1.25x1250 元常规回调，温和加码
4回撤 < 10%（默认）1.0x1000 元正常定投，不猜顶

档位经预算校准：最坏情况（深熊连续加码）单月支出 2000 元、持续一年额外支出约 6000 元——规则宁可温和到"肯定能执行"，也不激进到"理论最优但执行不了"。

利率修正项（叠加在上表结果上）

  • 10 年期美债收益率 > 4.5% 且 3 个月内上行 → 倍数 ×0.8（高利率压估值，略收敛）
  • 收益率 3 个月内下行 > 50bp → 倍数 ×1.2（宽松环境利好成长股）
  • 最终倍数四舍五入到 0.25 档，上限 2.0x（2000 元）

卖出/减仓纪律（先定原则，参数待你确认）

  • v1 采取"不主动择时卖出"立场：定投的卖出由你的人生资金规划决定，不由市场信号决定
  • 系统只做一件事：当 VIX < 13 且指数创新高且利率快速上行同时出现时，报告中提示"环境偏热，可考虑只投不加码"，不给卖出指令

每日触发提醒条件（daily-check）

触发提醒内容去重
回撤首次跌破 -10% / -20% / -30% 档位"进入 X 档加仓区，若有闲钱可执行计划外加投"每档位 30 天内只提醒一次
单日跌幅 > 4%大波动快讯 + 当前各信号快照每周最多一次
📌 已确认的参数（2026-07-05 与使用者确认，集中在 config.yaml 可改）： ① 月度基准 1000 元，倍数档位 1.25 / 1.5 / 2.0，上限 2.0x； ② 利率修正项保留（仅 ±20% 微调）； ③ 触发提醒同一档位 30 天去重。

5. 报告与推送形态

月度报告（HTML 邮件）结构

  1. 结论区（最上方大字）：本期定投倍数 + 一句话理由，例："本期建议 2.0x —— 纳指距高点回撤 23%，进入熊市加码区"
  2. 信号面板：回撤 / 200 日线 / 10Y 利率 / VIX / PE（若可得），每项带近一年迷你走势图（matplotlib 生成、内嵌 base64，无外链）
  3. 规则追溯：命中了哪条规则、修正项如何计算——让你能验证系统没算错
  4. AI 宏观点评：300 字以内，明确标注"参考信息，不构成规则输出"
  5. 历史记录表：过去 12 期的建议倍数与当时点位，直观看到纪律的复利

推送通道

  • 主通道：QQ 邮箱 SMTP（授权码方式，稳定免费，国内直连），HTML 正文
  • 凭据全部放 GitHub Secrets：SMTP_PASS、FRED_API_KEY、DEEPSEEK_API_KEY
  • 预留 notify 接口抽象，日后想加 Server酱微信推送只需新增一个实现

6. AI 点评模块

  • LLM 供应商可插拔，v1 用 DeepSeek（使用者已有 key，每月一次点评成本可忽略；OpenAI 兼容接口，日后想换 GitHub Models / Anthropic 改配置即可）。输入：当期全部信号数值 + 近一月主要宏观事件摘要（Finnhub 免费新闻 API 取市场类新闻标题）
  • Prompt 约束：只解释"市场正在发生什么、信号为什么长这样"，禁止给出与规则不同的仓位建议
  • 降级策略：API 失败时报告照常发出，点评区显示"本期点评生成失败"——AI 是点缀，永远不阻塞主流程

7. 数据存储与历史记录

  • 每期运行结果存 history/YYYY-MM.json（信号快照 + 建议倍数 + 命中规则），由 Actions 跑完后 commit 回仓库
  • 好处：Git 即数据库，零成本、天然带审计轨迹；月度数据量极小不会膨胀
  • 价格历史不落库，每次从 yfinance 现拉（^NDX 日线拉取只需数秒）

8. 测试与验证策略

  • 规则引擎单测：纯函数，覆盖每个档位边界（回撤 9.9% vs 10.0%）、修正项组合、上限截断
  • 历史场景快照测试：取 2020-03（疫情崩盘）、2022-12（加息熊底）、2024-07（高位）三个真实历史时点的数据固定为 fixture，断言系统给出符合预期的倍数——这是对规则合理性的"穷人回测"
  • 端到端 dry-run：python main.py --dry-run 本地跑通全流程但不发邮件，报告写到本地文件人工检查
  • 上线验收：手动触发 Actions（workflow_dispatch）发一封真实邮件到你邮箱确认格式

9. 风险点与应对

风险等级应对
yfinance 非官方接口，可能被 Yahoo 限流/改版中数据源模块化，预留 Stooq/Tiingo 备用实现；拉取失败时 Actions 告警邮件
纳指100 PE 无稳定免费源中降级为可选信号，缺失不影响主规则（见 §3）
GitHub Actions cron 有延迟（高峰期可延迟数小时）低月度报告对时效不敏感；每日检查设在美东盘后冗余时段
规则本身的市场风险：加码规则在长期阴跌中会持续加仓高这是策略固有属性而非 bug——倍数上限 4x 控制单期敞口；报告透明展示规则逻辑，最终决策权在人
Secrets 泄露（API key、邮箱授权码）低私有仓库 + GitHub Secrets，代码中零硬编码

10. 分阶段实施

阶段内容验收标准
P1 骨架数据拉取（^NDX/^TNX/^VIX）+ 规则引擎 + 单测本地跑 --dry-run 输出正确倍数，测试全绿
P2 报告HTML 报告渲染 + 邮件推送 + GitHub Actions 月度工作流手动触发 Actions，你的邮箱收到完整报告
P3 提醒每日触发检查工作流 + 去重逻辑用历史大跌日数据模拟，验证触发与去重
P4 点缀AI 点评 + FRED 利率修正 + PE 信号（尽力而为）点评出现在报告中且失败可降级

每阶段独立可用：P1 完成时系统就已经"能告诉你该投几倍"，后面都是体验增强。
